P3695 libairplay ELF interposition matrix

The inspected libairplay.so is AArch64 PIE/shared ELF with a dynamic symbol
table. The requested functions are exported as global T symbols. Crucially,
internal calls in the recovered code use PLT entries and R_AARCH64_JUMP_SLOT
relocations for several functions, including AirPlayReceiverSessionSetup,
AirPlayReceiverSessionScreen_Setup, Screen_Create, Screen_StartSession,
Screen_ProcessFrames, AirPlayGetFeatures, ScreenStreamCreate and
ScreenStreamProcessData.

No DT_FLAGS/DF_SYMBOLIC or BIND_NOW flag was shown by objdump -p. RELRO/GOT
hardening details cannot be fully decoded with the installed host tools, but
LD_PRELOAD resolution occurs before any post-start GOT protection. This is
static evidence of preemption potential, not a tested runtime result.

The strongest new result is that AirPlayReceiverSessionSetup is not only
exported: the library's own session-start path calls its PLT entry. A preload
replacement can therefore be technically possible without changing the ELF
file. The exact dynamic-loader behavior on the target and symbol versioning
remain untested.
